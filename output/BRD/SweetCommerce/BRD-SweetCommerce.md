# 1. Executive Summary

商家确认当前有手工接单、遗漏或重复记录、人工核对日期、制作产能缺乏控制、付款记录分散、顾客反复询问及缺少报表等问题。SweetCommerce 将标准下单、甜品台报价和商家履约纳入同一平台，以便追踪订单、收款和异常。

| 业务 | 客户流程 | 商家流程 |
| --- | --- | --- |
| 标准甜品 | 登录 → 选购固定商品、规格和口味 → 选取货方式与时间 → 复核 → 付款或等待现金单确认 | 核对付款或接受现金单 → 制作 → 自提或交接司机 → 完成 |
| 定制甜品台 | 登录 → 提交预算、人数和活动资料 → 确认报价 → 支付订金与尾款 → 查看活动安排和结算 | 评估产能和资源 → 报价 → 确认预约 → 布置与收拾 → 检查设备 → 结算追加费用 |

# 6. Booking Time and Production Capacity

## 6.1 时间规则

BR-PRE-001–007 覆盖提前时间、营业和关闭日期配置，以及对商品与所选日期的复核。

| 场景 | 业务规则 |
| --- | --- |
| 下单与申请 | 顾客可全天在线提交。商家营业时间 06:00–22:00，使用马来西亚时间 |
| 标准订单当日履约 | 所有标准商品均可接当天单，条件是商品可售、产能足够、准备时间允许且未错过 18:00 当天接单截止。自提或交接 Lalamove 最晚 21:00 |
| 标准订单未来履约 | 超过当天接单截止后，只能选择后续满足营业日期、准备时间和产能的时间 |
| 甜品台 | 最少提前 7 天。22:00 后提交，按次日开始计算提前天数。最终活动、布置和收拾时间由报价确认 |
| 商家配置 | 可设置关闭日期、未来产能和商品准备时间，并查看对已有订单的影响 |

## 6.2 产能占用

| ID | 场景 | 规则 |
| --- | --- | --- |
| BR-CAP-001–003 | 标准订单 | 按履约日配置商品数量总上限，可为个别商品设置单独上限。三种履约方式共享产能，同一笔订单按商品数量占用。最后名额不能被重复承诺 |
| BR-CAP-004 | 取消、拒绝或过期 | 未开始制作时释放标准订单名额。已开始制作则保留当日已用产能。甜品台释放尚未使用的预留资源 |
| BR-CAP-005 | 产能调整 | 商家可调整未来可用量及关闭日期。受影响的既有承诺由商家处理 |
| BR-CAP-006 | DuitNow 付款期 | 标准订单进入付款窗口时预留产能 30 分钟。按时上传凭证后保留到商家核对。核对时若无法按约定时间备货，核实收款后联系顾客改期或退款 |
| BR-CAP-007 | Cash 或等待运费 | 等商家接受 Cash 单或填写 Lalamove 运费时尚未预留。Cash 单由商家接受时占用。商家安排 Lalamove 时，顾客确认最终金额并通过产能复核后进入付款窗口 |
| BR-CAP-008 | 甜品台资源 | 商家人工检查并记录厨房、员工、往返、布置、收拾和设备所占时段。发报价后暂留资源，订金核对后转为已预约。商家按需调整同日标准订单可用制作量 |

# 7. Fulfilment Management

| ID | 履约方式 | 收费与操作 |
| --- | --- | --- |
| BR-DEL-012 | Self Pickup | 展示固定取货点及约定时间。无配送费。可选 Cash 或 DuitNow |
| BR-DEL-005–007 | 商家安排 Lalamove | 顾客提供地址及联系人，商家人工核实可送性、时间和运费。顾客复核含运费的最终金额后使用 DuitNow 付款 |
| BR-DEL-013 | 顾客安排 Lalamove | 顾客直接向 Lalamove 支付配送费。商品订单使用 DuitNow。商家按约定时间交接司机 |

# 9. Order and Booking Management

| 业务 | 关键状态与分支 |
| --- | --- |
| 标准 DuitNow | 需要商家报价的配送单先等运费确认。最终金额获顾客确认后进入待付款 → 凭证待核对 → 已确认 → 制作 → 已备妥 → 已取货或已交接 → 完成。另记录过期、付款不符、取消和配送异常 |
| 标准 Cash | 待商家接受 → 已确认 → 制作 → 已备妥 → 自提时收现并完成。商家可拒绝，逾约未取标记未取货 |
| 甜品台 | 已申请 → 已报价 → 待订金或凭证核对 → 已预约 → 待尾款或核对 → 待履约 → 布置及收拾 → 已完成或待追加费用。另记录过期、取消和改期 |

BR-ORD-001–009 覆盖唯一记录、后台查询、处理权限、状态变更、顾客查询及可追踪历史。商家记录关键变更的操作者、时间、前后状态和必要原因。订单、支付、退款和履约各自记录进度。BR-ORD-010 的取消和退款按第 10 节执行。

# 10. Payment, Cancellation, and Refunds

## 10.1 付款和对账

| ID | 场景 | 规则 |
| --- | --- | --- |
| BR-PAY-001–006 | 标准 DuitNow | 顾客按订单金额通过商家 DuitNow QR 全额付款，在付款窗口开始后 30 分钟内上传凭证。商家人工核对实际款项和金额后确认，订单才正式成立 |
| BR-PAY-009 | 标准 Cash | 仅适用 Self Pickup。商家先接受订单并安排制作，顾客取货时付款，商家记录收款。未取货标记未取货，尚未收取的现金无需退款 |
| BR-PAY-010 | 甜品台订金 | 只用 DuitNow。订金为报价总额 50%。报价最多有效 3 天，且订金最迟于活动前 4 天支付。报价显示实际截止时间，若已无法满足该期限，另约日期 |
| BR-PAY-011 | 甜品台尾款 | 原始服务尾款在活动前 3 天付清。逾期提醒并给予 24 小时宽限期，之后商家可取消预约。若订金凭证及时提交、商家在原尾款截止后才核款成功且仍可履约，顾客从核款确认起有 24 小时付款；若已来不及履约，商家与顾客协商改期或退款 |
| BR-PAY-012 | 活动后追加费用 | 与原始尾款分别列账。顾客在活动结束后 2 天内通过 DuitNow 支付追加账单 |
| BR-PAY-007–008 | 对账、退款和敏感资料 | 商家核对付款及退款、记录结果和原因。重复凭证或确认不重复入账。款项不符由商家拒绝或要求补款，疑似迟付或重复付款由商家核实。平台无需收集银行卡资料 |

未在付款窗口内上传凭证的标准订单过期并释放预留。已及时上传的凭证按第 6.2 节处理。商家核对前，上传凭证仅表示待核对。

## 10.2 取消与退款

| 场景 | 规则 |
| --- | --- |
| 标准订单尚未付款且商家未接受 | 顾客可以免费取消 |
| 标准 DuitNow 已付款或 Cash 已被商家接受 | 顾客不能自行取消。商家无法履约时取消订单，已收款全额退还。例外退款由商家决定并记录原因 |
| 甜品台尚未确认报价 | 可免费取消。未付订金的报价到期后释放资源 |
| 甜品台已付订金 | 订金不退。尾款到期前取消且尾款未付时，无须支付该笔尾款。活动前 3 天内取消，已付金额不退 |
| 商家无法履约、改期或不可抗力 | 商家无法履约时全额退还已收金额。改期或不可抗力由商家人工处理并记录 |

商业上线前由 zwong 确认对客条款、退款及争议处理流程。任何退款不得超过该笔交易的可退余额。

# 18. Assumptions and Constraints

- 首版以单一商家、MYR、马来西亚和 Web 为约束，由 zwong 承担商家业务决策及验收。
- 标准订单和甜品台共用商家制作资源，甜品台资源判断由商家人工完成。
- 系统按顾客账号隔离业务资料，经营后台使用单一专用管理员。
- 具体商品、价格、取货点、可服务区域和真实渠道为运营配置。开发可用示例配置。
- 原开发投入与 14–19 周估算仅保留为历史规划，首版日期由实际范围和资源另行安排。

# 20. Release Plan, UAT, and Release Gate

## 20.1 开发顺序

1. 先跑通账号、商品、跨设备购物车、标准订单、付款确认和三种履约方式。

| UAT-019 | 收拾、设备损坏、遗失或等待 | 设备清点可追踪，额外费用独立列账并在活动后 2 天内支付 |

## 20.3 商业上线检查

- zwong 验证实际商品、价格、取货点、区域、营业配置、对客条款和商家值守安排。
- 验证真实 DuitNow 收款、退款、Cash 对账、WhatsApp 通知、验证码及人工备用流程。
- 确认付款凭证、个人资料和审计记录的保留、删除、访问与客户请求处理规则。
- 完成管理员账号恢复、越权检查及备份恢复演练，确认恢复目标。
- 两类业务通过关键 UAT，由 zwong 验收并决定商业上线。
